      Logging in to **MAQSU ERP** is the first step to accessing your business
      dashboard, managing operational data, and performing daily activities.
      Follow the instructions below to sign in successfully.


      ### Step 1: Access Your Login Page


      Open a web browser and navigate to your organization's MAQSU ERP login
      URL.

      This URL is typically provided by your system administrator.


      ![Accessing MAQSU Login Page](/img/getting-started/login/0001.png)


      ***


      ### Step 2: Select the Appropriate Database for Your Organization


      Depending on your organization's setup, you may be required to select the
      database associated with your organization upon logging in. This step is
      only applicable if your company is using a multi-database setup. If only
      one database, simply proceed to step 3.


      ### Step 3: Enter Your Login Credentials


      * **Email or Username**
        Enter your registered email address or username.
      * **Password**
        Enter your secure password.

      ![MAQSU Login Screen](/img/getting-started/login/0002.png)


      After filling in all required information, click **Login** to continue.


      ***


      ### Tips


      * Please note that creating a new account is not permitted. Your **system
      administrator** will provide you with the necessary login credentials.

      * Ensure **Caps Lock** is turned off when entering your password.

      * If you forgot your password, use the **Forgot Password** option to reset
      it.

      * Contact your **system administrator** if you are unsure which database
      to select.


      ***


      You are now ready to start using **MAQSU ERP**.

          ### Access Rights


          This is the core security system in mAQSU.


          Security flow:


          ![](/img/getting-started/user_account/user_roles/0007.png)


          Example:


          * Accountant role → Access to Accounting only

          * Sales role → No access to Accounting

          * Admin role → Full system control


          Permissions you control in Roles:


          * Read (view data)

          * Create (add data)

          * Write (edit data)

          * Delete (remove data)


          If access is not given → user cannot open that module.


          ### Record Rules


          This is more advanced security.


          It controls which records a user can see, not just modules.


          Example:


          * Branch user → Can only see their branch invoices

          * Employee → Can only see their own records

          * Manager → Can see all records


          #### Menu Security (Hide Menu)


          Using the **Hide Menu** tab in Role Management, administrators can
          hide

          specific menus from users based on their role.


          You can hide menus such as:


          * Finance

          * HR

          * Inventory

          * Settings


          If a menu is hidden, the user will not see it in the sidebar and
          cannot

          access that module even if they try to navigate directly.


          This is useful for restricting access to sensitive modules.


          #### Action & Button Restrictions (Hide Action / Hide Button &
          Tab)


          MAQSU allows administrators to control visibility of specific actions,

          buttons, and interface elements to reduce operational risks.


          You can restrict:


          * Delete button

          * Post button

          * Approve actions

          * Export options

          * Edit buttons

          * Sensitive tabs inside forms


          This prevents accidental data deletion, unauthorized approvals,

          and unwanted data exports.


          #### Recommended Security Setup (Role-Based)


          A proper role-based security structure is recommended for
          organizations:


          *Admin*


          * Full access to all modules

          * Access to Settings and Role Management

          * Manage users, roles, and system configuration


          *Accountant*


          * Access to Accounting and Financial Reports

          * Read, Create, and Write permissions enabled

          * Delete permission disabled for safety

          * No access to HR or System Settings


          *Staff / User*


          * Read-only or limited Create/Write access

          * No Delete permissions

          * Restricted module visibility based on job role


          Following the principle of least privilege ensures better data
          protection,

          system stability, and compliance with internal security policies.

      - link: /currencies

        body: |

          A **Currency** represents the system of money used for recording and valuing transactions in MAQSU ERP (e.g., USD, KHR, EUR). Proper currency configuration allows your company to operate both locally and internationally while maintaining accurate financial records in your General Ledger.

          > **Note:** MAQSU ERP comes with commonly used currencies already available. You can activate existing currencies or create new ones to match the markets where your business operates.

          ---

          ### Step 1: Go to Currency Configuration

          From the left sidebar, click **Accounting**. Then, from the top navigation menu, go to **Configuration** → **Currencies**.

          ![](/img/getting-started/currencies/0001.png)
          ![](/img/getting-started/currencies/0002.png)

          ---

          ### Step 2: Click Create

          Click the **Create** button to add a new currency or define a new exchange rate. This opens the currency form where you can define how the currency behaves across accounting transactions and reports.

          ![](/img/getting-started/currencies/0003.png)

          ---

          ### Step 3: Fill Out Currency Information

          #### 1. Top-Level Configuration
          * **Currency Name** – The ISO code or name (e.g., USD, KHR).
          * **Currency Unit** – The full name of the primary unit (e.g., Dollar, Riel).
          * **Currency Subunit** – The name of the fractional unit (e.g., Cents, Sen).
          * **Active** – Ensure this checkbox is selected so the currency is available for use in transactions.

          ![](/img/getting-started/currencies/0004.png)

          #### 2. Exchange Rate Configuration
          This section determines how the currency is converted relative to your company’s base currency.

          1. Click on the **Rates** smart button at the top of the form.
          2. Click the **Create** button to add a specific rate.
          3. Enter the **Rate**: The conversion value (e.g., if 1 USD = 4000 KHR, enter `4000`).
          4. Enter the **Date**: The effective date for this specific exchange rate (DD-MM-YYYY).

          ![](/img/getting-started/currencies/0005.png)
          ![](/img/getting-started/currencies/0006.png)

          ---

          ### Step 4: Save the Configuration

          Once all details are verified, click the **Save** button. Your currency settings will now be applied across all modules, including Invoices, Payments, and Financial Statements.

          ---

          <Noted type="info" title="Automatic Exchange Rate Update (NVC)" image="/img/icon/tip.png">
          MAQSU ERP can automatically fetch and update exchange rates based on the National Bank (NVC). This reduces manual data entry and ensures your financial valuations remain accurate and compliant with the latest official rates.
          </Noted>

          For more details on how to enable auto update exhange rate, see the [Enable Auto NVC Guide](/accounting/aged-payable).

          The **Chart of Accounts** (COA) is an organized system for categorizing and tracking every financial transaction in your business. Think of these as specific "folders" where activities are sorted to keep your General Ledger structured, accurate, and ready for reporting.

          > **Note:** MAQSU ERP comes pre-configured with a standard Chart of Accounts. You can add, edit, or deactivate accounts to better fit your specific business structure.

          ---

          ### Step 1: Access Chart of Accounts

          From the left sidebar, click **Accounting**. Then, from the top navigation menu, go to **Configuration** → **Accounting** → **Chart of Accounts**.

          ![](/img/getting-started/chart-of-accounts/001.png)
          ![](/img/getting-started/chart-of-accounts/002.png)

          ---

          ### Step 2: Click Create

          Click the **Create** button to open a new account entry line. This allows you to define a new category for your financial tracking.

          ![](/img/getting-started/chart-of-accounts/003.png)

          ---

          ### Step 3: Fill Out Account Information

          Enter the following details to define the account's behavior and classification:

          * **Code** – A unique numerical identifier (e.g., `101100`). Consistent coding helps group similar accounts (Assets usually start with 1, Liabilities with 2, etc.).
          * **Account Name** – A descriptive title (e.g., "Petty Cash - Main Office").
          * **Type** – Select the category (Asset, Liability, Equity, Income, or Expense). This is vital as it determines where the account appears on your Balance Sheet or P&L.
          * **Default Taxes** *(Optional)* – Set a default tax rate that will auto-populate whenever this account is selected in an invoice or bill.
          * **Account Currency** – Specify the currency if the account is restricted to a specific one (e.g., a KHR Bank Account).
          * **Group** – Select a higher-level group for consolidated financial reporting.

          ![](/img/getting-started/chart-of-accounts/004.png)

          ---

          ### Step 4: Save the Account

          Once the information is verified, click the **Save** button. The new account will now be available for selection in journals, invoices, and manual entries.

          <Noted type="info" title="Important Note" image="/img/icon/notes.png">
          For security and data integrity, the system will not allow you to delete an account if it already contains recorded transactions. If an account is no longer needed but has history, use the **Deprecated** (or Inactive) setting to hide it.
          </Noted>

          Completing your **Chart of Accounts** ensures that your financial reports, like the Balance Sheet, are accurate from day one.

          For more details on setting up the rules that govern these accounts, see the [Setup Taxes Guide](/accounting/taxes).

      - link: /taxes
        title: Taxes
        body: |

          A **Tax** is a levy imposed by the government on a taxpayer's income or profits. In MAQSU ERP, taxes are configured as specific rules that automate the calculation of government levies on sales and purchases, ensuring your General Ledger remains organized and compliant.

          > **Note:** By default, MAQSU ERP comes pre-configured with standard taxes for sales and purchasing. If your business requires additional or custom tax rates, follow the systematic steps below to define them.

          ---

          ### Step 1: Go to Taxes

          From the left sidebar, click **Accounting**. Then, from the top navigation menu, go to **Configuration** → **Taxes**.

          ![](/img/getting-started/taxes/0002.png)
          ![](/img/getting-started/taxes/0001.png)

          ---

          ### Step 2: Click Create

          Click the **Create** button at the top-left of the Taxes list page to open a new blank tax configuration form.

          ![](/img/getting-started/taxes/1.png)

          ---

          ### Step 3: Fill Out Tax Information

          Define the properties and behavior of your new tax by filling in the following sections:

          #### 1. Top-Level Configuration
          * **Tax Name** – The label displayed to users (e.g., VAT - Sales of Goods 10%).
          * **Tax Computation** – Usually set to **Percentage of Price**. For example, a $100 sale with a 10% tax will calculate a $10 tax amount.
          * **Tax Scope** – Select **Sales** (for Customer Invoices) or **Purchase** (for Vendor Bills).
          * **Amount** – The numerical percentage value (e.g., 10.00%).
          * **Active** – Ensure this is checked so the tax is available for use in transactions.

          ![](/img/getting-started/taxes/0004_1.png)

          #### 2. Repartition for Invoices
          This section maps the tax to your General Ledger (GL) accounts.
          * **Base (Empty)** – Tracks the "Untaxed Amount" (posted to your Sales/Income account).
          * **100% of Tax** – Assign the liability account where the tax collected will be stored (e.g., **201900 VAT Output**).

          ![](/img/getting-started/taxes/0004_2.png)

          #### 3. Repartition for Credit Notes
          This section mirrors the invoice settings to ensure taxes are **reversed** correctly when issuing refunds.
          * Using the same account (e.g., **201900 VAT Output**) will decrease your tax liability when a sale is reversed.

          ![](/img/getting-started/taxes/0004_3.png)

          #### 4. Advanced Options
          * **Label on Invoices** – The specific text that prints on the customer's physical document.
          * **Tax Group** – Used to group similar taxes for financial reporting (e.g., VAT 10%).
          * **Included in Price** – If unchecked (Tax Exclusive), tax is added on top of the price ($100 + $10). If checked (Tax Inclusive), the tax is extracted from the price.
          * **Affect Base of Subsequent Taxes** – Check this to enable **compounding**, where a second tax is calculated on the (Price + first tax).

              * **Standard Price**: Products are valued at a manually fixed cost.

              * **First In First Out (FIFO)**: Cost is based on the actual price paid for the oldest units.
          * **Inventory Valuation**:
              * **Manual**: Periodic manual entries are required to update stock value in accounting.

          * **Expense Account**: The account used to record the cost of the items sold during the transaction (e.g., *501100 Cost of Goods Sold*).

          #### Account Stock Properties
          These fields are required for **Automated Inventory Valuation** to function:
          * **Stock Input Account**: A temporary "bridge" account that holds value when goods are received but not yet invoiced.
          * **Stock Output Account**: A temporary account that holds value when goods are delivered but the customer hasn't been invoiced yet.
